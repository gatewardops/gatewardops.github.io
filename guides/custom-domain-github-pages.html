Custom domain on GitHub Pages

How to serve a static site from your own domain with free HTTPS, using GitHub Pages and a few DNS records.

This is how gatewardops.com is set up.

1. How the pieces fit together

Three separate things make a website reachable:

  • Repository: where the files and their history live (GitHub).
  • Hosting: the servers that deliver the files to visitors (GitHub Pages).
  • Domain: the address people type. DNS records at your registrar point that address at the hosting.

Because they are separate, you can later move hosting without touching the files. Only the DNS records change.

2. Create the repository

For a user site, name the repository <username>.github.io. Put index.html in the root of the main branch, plus a file named CNAME (no extension) that contains only your domain:

example.com

GitHub Pages reads this file to know which domain the site answers to. If you set the domain in the settings instead, GitHub creates the file for you.

3. Add the DNS records

At your domain registrar, add these records. The apex (@) needs A records, because a CNAME is not allowed at the root of a zone. The www subdomain uses a CNAME to your GitHub Pages hostname.

TypeHostValue
A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
CNAMEwww<username>.github.io

For IPv6, you can also add AAAA records for @: 2606:50c0:8000::153, 2606:50c0:8001::153, 2606:50c0:8002::153 and 2606:50c0:8003::153.

Remove any old A, AAAA or CNAME records for the same hosts, such as a registrar's parking page, or visitors may land on the wrong server. Then check the records from a terminal:

# PowerShell
Resolve-DnsName example.com -Type A
Resolve-DnsName www.example.com -Type CNAME

# Linux / macOS
dig +short example.com A
dig +short www.example.com CNAME

4. Configure GitHub Pages

  1. Open the repository's Settings → Pages.
  2. Under Build and deployment, choose Deploy from a branch, branch main, folder / (root).
  3. Under Custom domain, enter your apex domain (for example example.com) and save. Wait for DNS check successful.

With both the apex and www records in place, GitHub redirects www.example.com to example.com automatically.

If the site is plain HTML, add an empty file named .nojekyll to the root. Pages then serves the files as they are instead of running them through Jekyll, so deployments are faster.

5. Verify the domain

Verification proves the domain is yours, so nobody else can attach it to their own Pages site if your site is ever unpublished (a "domain takeover"). In your account, go to Settings → Pages → Add a domain. GitHub shows a TXT record like this:

Type:  TXT
Host:  _github-pages-challenge-<username>
Value: <random code from GitHub>

Add it at your registrar, click Verify, and leave the record in place afterwards.

6. Enforce HTTPS

After the DNS check passes, GitHub requests a free TLS certificate from Let's Encrypt. That can take from a few minutes up to an hour. Once it is ready, tick Enforce HTTPS on the Pages settings page, and plain http:// requests are redirected to https://.

# Should answer 301 with Location: https://example.com/
curl -sI http://example.com/

7. Keep personal details out

A public repository publishes more than the website itself. Check these before your first commit:

  • Commit email. Every commit records an author email, and anyone can read it by adding .patch to a commit URL. In Settings → Emails, turn on Keep my email addresses private, and set Git on your computer to the noreply address: 
    git config --global user.email "<id>+<username>@users.noreply.github.com"
    Changing the setting does not hide commits you have already made. Those keep the old email until the history is rewritten.
  • WHOIS. Turn on privacy protection at your registrar, so the public registration record shows a proxy service instead of your name and address. Check it with an RDAP lookup.
  • File metadata. Photos and PDFs can contain names, GPS locations and device details. Strip the metadata (EXIF) before uploading.

8. Troubleshooting

503 or 404 right after setup

The first deployment takes a minute or two. Look in the repository's Actions tab for the pages build and deployment run. Once it has finished, the error usually goes away within a few minutes.

"DNS check unsuccessful"

The records have not reached GitHub yet, or an old record is still there. Compare the output of Resolve-DnsName or dig with the table above. Changes can take up to a day to spread, depending on the record's TTL.

Enforce HTTPS is greyed out

The certificate has not been issued yet. Wait, then reload the settings page. If it stays greyed out, remove the custom domain, save, add it again and save. That restarts the certificate request.

The custom domain disappears after a push

The CNAME file is missing from the branch Pages builds from. Commit it to the root of the repository.
